# 冰冰冰结束后才启动双跳

## 当前规则
idle → tapping → waitingForBingEnd → laughing → idle。
phase 由现有 motion 状态管理；同步 ref 只用于事件入口去重，避免 React 批量更新时重复触发。
复用原 taps 和 1200ms 连击窗口，没有新增音效计数器或延迟计时器。

第三拍清空本轮计数、取消原连击超时并锁定本轮：
- 冰冰冰仍处于请求播放/播放中：只进入等待，画面保持待机和肚皮回弹。
- 冰冰冰已经 ended、播放失败或加载错误：直接进入双跳。
- 正常播放时只由真实 ended 事件释放等待，不使用音频时长估算。
- 等待期间额外点击可以产生原有肚皮反馈，但不计数、不重播、不重复启动大笑。
- 大笑开始时同时记录原统一开始时间并启动一次 laugh.mp3。
- 双跳保持每轮 1500ms、两轮 3000ms，第二跳不重播，结束释放锁。
- 没有新一轮输入时，大笑尾音继续自然结束；若尾音尚在播放就开始新一轮拍肚，
  新轮首拍暂停旧尾音再播放冰冰冰，避免两个音效同时出声。

## 修改文件
- src/App.jsx：上述 phase 转换、等待入口、事件回调和卸载清理。
- src/features/audio/bingSequence.js：持久 ended/error/abort 监听、播放结果与代次保护。
  原轮 play Promise 晚到的失败不会触发新轮；dispose 后移除监听并忽略所有异步回调。
- src/features/audio/slapSound.js：同步发起首拍播放，返回成功/失败 Promise。
- src/features/audio/laughSound.js：删除打断正常冰冰冰的 pause 调用，仅负责单次大笑。
没有修改动画配置、素材、音频、CSS、布局或数据库。

## 异常
冰冰冰 play 被拒绝、同步抛错、媒体 error/abort 时标记失败。
如果此时在等待，立即只启动一次大笑；失败音频暂停，避免错误恢复后叠音。
如果在第三拍之前已经失败，第三拍直接进入大笑。
等待加载/缓冲中的正常播放不会因猜测时长而跳过；没有人为超时。
遵循浏览器音频权限，大笑本身无法播放时动画仍会完成，不绕过浏览器策略。

## 验证
Edge 390×844 CSS px，实际触摸模拟与 MP3 播放：
- 快速三拍仍播放完整冰冰冰，等待时没有大笑 play 请求，待机和回弹正常。
- 正常 ended 之后约 0.2ms 请求大笑播放，无中途 pause、重播或重叠。
- 慢速三拍时冰冰冰已自然结束，第三拍后约 17ms 开始大笑，不再等待。
- 等待期间快速额外点击只有一个冰冰冰播放和一个大笑播放。
- 两次完整帧序列及人脸跟随通过；观测双跳约 1.501s + 1.517s（含刷新采样误差）。
- 动作结束回待机，下一轮正常。
- 播放被拒绝、第三拍后才拒绝、等待中 error、实际网络加载失败均能进入大笑。
- 卸载/销毁移除事件监听，晚到 Promise 不再回调。
- 原有换脸、命名、头像库增删改查及持久化回归通过。
- npm.cmd run build 成功，无浏览器运行报错。
